# Code signing policy

Free code signing provided by SignPath.io, certificate by SignPath Foundation.

This is the intended production signing arrangement only. YOMA has not been approved by SignPath Foundation and no artifact may be described as SignPath-signed until an actual SignPath signing request has been approved and the returned signature has been independently verified.

## What is signed

The intended Windows release artifacts are the YOMA-authored release executables and the final YOMA installer. Upstream runtime and native dependency files may be included when permitted by their licenses and the SignPath artifact configuration, but they must not be signed with YOMA’s SignPath certificate.

The exact file list is generated by the release manifest and enforced by the checked-in SignPath artifact configuration after the project is accepted.

## Release controls

- Production signing is restricted to the approved release workflow and release branches.
- Every production signing request requires the configured human approval process.
- Source, build scripts, workflow configuration, and installer configuration are part of the reviewed release input.
- Private signing keys and SignPath credentials remain outside the repository.
- Smart App Control and Windows Code Integrity are not disabled or weakened.

## Privacy

YOMA can access local documents, local application data, microphone input when voice features are used, and external services when the user configures integrations. See [PRIVACY.md](PRIVACY.md) for the implementation-based description and the maintainer’s required deployment disclosures.
